## 실제 발견/수정한 문제 (계획 단계에서 예상 못 했던 것들)
1. **Kakao Maps SDK 로딩 타이밍**: `<script>` 태그의 `onload`가 발생해도
   `window.kakao.maps.LatLng`가 생성자가 아닌 상태였다(SDK 부트스트랩 파일이 내부적으로
   지도 서브시스템을 비동기로 추가 로드하는 구조라, 외부 스크립트 자체의 로드 완료와
   지도 API 준비 완료가 다른 시점). `autoload=false` 쿼리파라미터를 추가하고
   `window.kakao.maps.load(callback)`으로 감싸는 Kakao 공식 패턴으로 교체해 해결
   (`src/app/orders/new/RouteMap.js`).
2. **프록시 게이팅이 HTTP 메서드를 구분하지 않던 버그**: `src/proxy.js`의
   `PATH_FLAGS`는 pathname만 보고 게이팅하는데, `/orders`는 Stage 1(GET, 목록 페이지)과
   Stage 2(POST, 오더 등록 제출)가 같은 경로를 공유한다. 스테이징에서
   `NEXT_STAGE1_ORDERS_ENABLED=true`일 때 `POST /orders` 오더 등록 제출이 Next.js
   페이지 라우터로 넘어가버려(Next는 메서드 구분 없이 그냥 페이지를 렌더링) 요청 바디가
   조용히 무시되고 200 응답에 HTML만 돌아오는 실제 버그를 실사용 테스트 중 발견했다.
   `GET`이 아닌 모든 요청은 플래그 상태와 무관하게 항상 Express로 보내도록 고쳐서 해결
   (src/app/** 아래 페이지는 전부 GET 전용이므로 이 규칙이 다른 슬라이스에 영향 없음).
3. **Kakao Maps JS 키의 도메인 제한과 Vercel Preview URL의 구조적 불일치**: 매 배포마다
   랜덤 서브도메인이 생기는 Preview URL은 콘솔에 도메인을 등록해도 다음 배포에서 무효가
   된다. `vercel alias set`으로 고정 스테이징 도메인(`b2bcarkr-staging.vercel.app`)을
   만들어 재배포해도 같은 alias만 갱신하는 방식으로 해결 — 앞으로의 Stage에서도 재사용
   가능한 인프라로 남긴다.
