# AI 단계별 전환 작업지시서 (Express + EJS -> 점진 전환)

## 0. 목적과 원칙
- 목적: 운영 중단 없이 UI/프론트 레이어를 점진적으로 현대화한다.
- 원칙: 전면 전환 금지, 단계별 전환만 허용한다.
- 원칙: 각 단계는 계약 테스트 + 스테이징 실사용 검증 + 롤백 경로 점검을 모두 통과해야 다음 단계로 이동한다.
- 원칙: 기존 Express 라우트, 세션/RBAC, DB 계약은 단계별로 유지한다.

## 0-1. 현재 코드 상태 보정
- AI 챗봇 화면은 단순 정적 화면이 아니라, 세션 유지/idle 판정/health 체크/최근 항목 삭제/상담 플로우가 결합된 운영 화면이다.
- 따라서 Next 전환 1단계의 우선 대상은 읽기 전용 대시보드/목록이며, AI 챗봇은 3단계에 가까운 고난도 영역으로 취급한다.
- 최근 항목 삭제는 사용자 화면 전용 숨김(user_hidden_at)이며, 관리 화면은 유지한다.
- AI health는 1분 주기 폴링이며, 실제 idle은 챗봇 입력 activity 기준으로 판정한다.
- 이 문서는 전환 순서/게이트를 정의하는 문서이고, 프레임워크 전환 자체를 이미 수행했다는 뜻은 아니다.

## 1. 공통 운영 규칙
- 릴리스 단위: 단계 내에서도 화면/기능을 작은 배치로 분할 배포한다.
- 배포 전략: Vercel 프로덕션 별칭은 최종 검증 후에만 전환한다.
- 기능 플래그: 신규 UI는 플래그로 켜고 끈다. 기본값은 OFF.
- 데이터 계약: 요청/응답 스키마와 폼 필드명은 기존 계약을 유지한다.
- 마이그레이션: DB 변경은 최소화하고, 필요 시 앱 배포와 분리해 선적용/후적용 계획을 문서화한다.

## 2. 단계 게이트 (필수)
각 단계 완료 판정은 아래 3가지 모두 충족 시에만 가능하다.
1. 계약 테스트 통과
2. 스테이징 실사용 검증 통과
3. 롤백 경로 점검 완료

미충족 시:
- 프로덕션 반영 금지
- 원인 분석 후 같은 단계에서 수정 반복
- 다음 단계 착수 금지

## 3. 단계별 전환 계획

### 1단계: 읽기 전용 페이지 전환 (대시보드/목록 일부)
### 범위
- 읽기 전용 화면부터 전환한다.
- 우선 대상:
  - 대시보드
  - 오더 목록(조회 전용 동작)
  - 문의 목록(조회 전용 동작)
  - 상담 세션 목록(읽기 위주 영역)

### 현재 코드 기준 우선순위
- 1순위: 대시보드
- 2순위: 오더 목록/필터
- 3순위: 문의 목록
- 4순위: 상담 세션 목록의 읽기 전용 카드/리스트
- 보류: AI 챗봇 입력/실시간 플로우는 1단계 대상에서 제외

### 제외
- 생성/수정/삭제 폼
- 실시간 송수신
- 결제/요금 계산 입력

### 계약 테스트 체크리스트
- 페이지 응답 코드 200
- 기존 필터 파라미터 동작 동일
  - 지사, 상태, 기간, 검색어
- 목록 정렬/페이지네이션 결과 건수 동일
- 권한별 노출 동일
  - admin, branch_manager, client
- 숫자/통화/상태 배지 표기 규칙 동일

### 스테이징 실사용 검증
- 운영 담당자 시나리오 10건 이상 수동 점검
- 기존 화면 대비 데이터 누락/중복 여부 확인
- 모바일/데스크톱 레이아웃 확인
- 페이지 전환 체감 및 오류 콘솔 확인

### 롤백 조건
- 조회 데이터 오차 1건 이상
- 권한 오노출 1건 이상
- 스테이징 JS 에러 재현 가능 이슈 1건 이상

### 롤백 방법
- 기능 플래그 OFF로 즉시 기존 EJS 렌더로 복귀
- 필요 시 직전 Vercel 배포로 재배포
- 데이터 스키마 변경 없음이 원칙

### 단계 완료 기준
- 계약 테스트 100% 통과
- 운영 검증 승인(서명/체크리스트)
- 롤백 리허설 1회 성공

---

### 2단계: 오더 폼 전환
### 범위
- 오더 등록/수정 관련 입력 UI 전환
- 포함 기능:
  - 예약일시(연/월/일, 시/분)
  - 예약 기준(픽업/인도) 및 역산 표시
  - 주소/경유지/연락처 입력
  - 차종/차량번호 분리
  - 요금 프리뷰 및 도선 관련 표시

### 계약 테스트 체크리스트
- POST /orders 요청 필드 계약 동일
  - reserved_date, reserved_time
  - pickup_reserved_date, pickup_reserved_time
  - vehicle_type, vehicle_number
  - memo_customer, fare_amount
- 폼 유효성 검증 규칙 동일
- 예약 기준 전환 시 저장 값 동일
- 요금 프리뷰 API 결과 반영 동일
- 기존 hidden 필드 동기화 누락 없음

### 스테이징 실사용 검증
- 핵심 시나리오 20건 이상
  - 일반 오더
  - 경유지 포함
  - 도착지 기준 역산
  - 월말/윤년 날짜 경계
  - 차종 미입력/입력 케이스
- 주소 검색/지도/경로탐색 연동 확인
- 요금 계산 문구와 저장값 대조

### 롤백 조건
- 저장 필드 누락 또는 필드명 불일치
- 요금 계산 결과 차이
- 예약 기준 계산 오류
- 운영 업무 중단 이슈

### 롤백 방법
- 신규 폼 플래그 OFF
- 기존 EJS + 정적 JS 폼으로 즉시 복귀
- 배포 롤백 필요 시 직전 안정 배포로 복귀

### 단계 완료 기준
- 계약 테스트 100% 통과
- 실제 주문 생성/수정/조회 왕복 검증 완료
- 롤백 리허설(폼 작성 중 전환 포함) 성공

---

### 3단계: 상담관리/실시간 플로우 전환
### 범위
- 상담 카드/상세, 실시간 메시지, 상담원 배정/상태 전환
- 포함 기능:
  - 세션 선택/메시지 로딩
  - EventSource 스트림
  - 읽음 상태/담당자 표시
  - 상담 상태 전이(bot -> needs_agent -> agent_active -> closed)
  - 상담 중 오더 접수 폼 연동

### 계약 테스트 체크리스트
- /chat/* 엔드포인트 요청/응답 스키마 동일
- 상태 전이 규칙 동일
- 읽음/미읽음 표시 일관성 유지
- 세션 삭제/종료/재개 동작 동일
- AI 인입 세션에서 오더 전환 데이터 무결성 유지

### 스테이징 실사용 검증
- 동시 사용자 2~3명 실시간 시나리오 테스트
- 네트워크 일시 끊김/재연결 시 복구 동작 확인
- 장시간 세션(30분+) 메모리/성능 확인
- 상담원 업무 시나리오 15건 이상 리허설

### 롤백 조건
- 실시간 메시지 유실/중복
- 상태 전이 꼬임
- 상담원 배정 데이터 불일치
- 오더 전환 데이터 손실

### 롤백 방법
- 실시간 신규 UI 플래그 OFF
- 기존 상담 관리 UI로 즉시 복귀
- 필요 시 직전 안정 배포로 롤백

### 단계 완료 기준
- 계약 테스트 100% 통과
- 동시접속 실사용 검증 승인
- 장애 대응 훈련(롤백 포함) 성공

## 6. 배포/롤백 운영 템플릿
### 배포 전
- 최신 마이그레이션 적용 여부 확인
- 환경변수 변경 여부 확인
- 서비스워커/캐시 영향 여부 확인

### 배포 후
- 핵심 URL 스모크 테스트
- 오류 로그 15분 모니터링
- 사용자 공지 필요 여부 판단

### 롤백 트리거
- P1: 즉시 롤백
- P2: 30분 내 개선 불가 시 롤백
- P3: 핫픽스 우선, 반복 시 롤백

## 7. 이 프로젝트 전용 주의사항
- 로컬 npm start 실패가 포트 충돌/권한/환경 영향일 수 있으므로, 코드 불량과 분리해서 판정한다.
- Supabase 마이그레이션 누락 시 런타임 오류가 발생할 수 있으므로, 앱 배포와 별도로 DB 반영 상태를 매번 확인한다.
- 예약일시/예약기준/요금/상담상태처럼 도메인 민감 필드는 UI 변경보다 데이터 계약 검증을 우선한다.
