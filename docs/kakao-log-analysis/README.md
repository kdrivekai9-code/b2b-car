# 탁송 상담톡 로그 분석 — 재현용 스크립트

`docs/kakao-chatbot-upgrade-plan.html`(탁송 상담톡 챗봇 고도화 기획서)의 모든 수치를 만들어낸
스크립트다. 표본은 핸들모빌리티 탁송 상담톡 로그 2024-04-22 ~ 2026-08-06, 메시지 10,551건 /
요청 1,206건.

## 원본 로그는 여기 없다

고객·기사 실명과 휴대폰 번호가 그대로 들어 있어 저장소에 넣지 않았다. 구글 드라이브 원본을
받아 임시 디렉터리에 두고 쓴다. 저장소 안으로 복사하지 말 것.

```
python3 parse_log.py <로그파일> msgs.json   # 먼저 실행 — 나머지 스크립트가 msgs.json을 읽는다
```

## 스크립트

| 파일 | 산출 | 기획서 |
|---|---|---|
| `parse_log.py` | 날짜·요청 블록·화자·시각 단위 구조화 → `msgs.json` | 표 1-1 |
| `routes.py` | 배차 통보 커버리지, 룰 파서 필드 추출률, 차종·거점 빈도 | 표 2-1 |
| `kinds_fixed.py` | 접수 유형·부가 조건·운행 방향 | 표 2-2 |
| `agent_final.py` | 상담원 발화 단일 라벨 분류 + 자동화 등급 | 표 2-3 |
| `agent_flow.py` | 첫 응답 지연, 시간대·요일·월별 분포 | 표 2-4 |
| `intents.py` | 접수 외 고객 메시지 인텐트 13종 분류 | 표 2-5 |
| `automatable.py` | 요청 단위 자동화 가능성(60.8% / 28.7% / 10.5%) | 3절 |

`agent_final.py`는 `agent_flow.py`가 만든 `agent_unmatched.json`을 참조하지 않고 독립 실행된다.
`intents.py` / `agent_final.py`는 미분류 메시지를 각각 `unmatched2.json` /
`agent_unmatched2.json`으로 떨어뜨리는데, **이 파일들에는 개인정보가 들어 있으므로**
저장소로 옮기지 말 것.

## 분류 기준을 고칠 때

키워드 정규식 기반이라 기준을 바꾸면 수치가 바뀐다. 초기 버전은 접수 유형 집계에서
"군포 탁송 **및 책임보험가입** 신청합니다" 형태(전체의 13%)를 정규식이 걸러내지 못해 표본이
편향됐었고, `kinds_fixed.py`가 그걸 바로잡은 버전이다. 기준을 바꾸면 기획서 본문의 수치도
같이 갱신해야 한다.
